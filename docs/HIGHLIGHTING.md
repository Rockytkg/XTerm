# 终端关键字高亮使用指南

XTerm 支持在终端输出中按规则高亮关键字和正则匹配内容，适合在日志、设备回显中高亮错误、警告、状态词等信息。高亮按"方案"组织，方案绑定终端主题，并需要在连接上单独开启。

## 快速开始

1. 打开 **设置 → 关键字高亮**，点击 **新建方案** 创建方案，或点击 **导入** 直接导入示例方案（见下文"示例方案"）。
2. 在方案编辑弹窗中为方案选择**生效主题**（即终端主题，如暗色/亮色主题）。
3. 进入方案添加规则：关键字或正则、匹配方式、颜色与生效方式。
4. 打开目标连接的连接配置，在**会话选项**中开启 **关键字高亮**。
5. 当终端使用方案绑定的主题时，该方案的规则即对此连接生效。

两个条件缺一不可：方案必须绑定当前终端主题，且连接必须开启关键字高亮开关。

## 规则字段

| 字段 | 说明 |
| --- | --- |
| 匹配方式 | `文本`（子串匹配）或 `正则`（JavaScript 正则） |
| 关键字或表达式 | 文本模式下可用 `\|` 分隔多个关键字，共享同一颜色；正则模式直接填写表达式 |
| 区分大小写 | 默认不区分 |
| 生效方式 | `文字颜色`（前景）或 `背景颜色`（背景，自动计算对比色文字） |
| 颜色值 | `#rrggbb` 十六进制颜色 |

规则按顺序参与匹配；同一行的多处匹配都会渲染。

## 主题绑定

- 每个终端主题只能归属一个方案：把主题绑给新方案时，会自动从原方案移除。
- 常见做法是暗色、亮色主题各建一个方案（颜色分别适配两种底色），主题切换时规则随之切换。
- 未绑定任何主题的方案不会生效。

## 导入与导出

设置 → 关键字高亮 工具栏提供 **导入**，方案卡片提供 **导出**，均通过原生文件对话框选择路径。

文件格式为 JSON 数组，每个元素是一个方案（`name` + `rules`），与导出产物一致：

```json
[
  {
    "name": "运维日志高亮",
    "rules": [
      {
        "matchType": "regex",
        "pattern": "(?<![A-Za-z0-9_-])(?:ERROR|FAILED|DENIED)(?![A-Za-z0-9_-])",
        "caseSensitive": false,
        "effect": "foreground",
        "color": "#ff5555"
      }
    ]
  }
]
```

导入时后端逐条校验规则：匹配方式必须是 `text` / `regex`，生效方式必须是 `foreground` / `background`，颜色必须是 `#rrggbb`，表达式不能为空；任一规则不合法则整个导入失败。

注意：

- **导入会整体替换现有方案列表**，导入前请先导出需要保留的方案。
- 导入的方案不携带主题绑定，导入后需要重新为方案选择生效主题。
- 导出按方案进行，一次导出一个方案（数组中一个元素）。

## 示例方案

`examples/highlight-schemes/` 提供面向网络与 Linux 运维场景的成套方案，可直接导入：

- `network-ops-dark.json`：暗色主题配色。
- `network-ops-light.json`：亮色主题配色。

两者覆盖日志级别（`%AAA/1/...` 形式）、错误/警告/正常状态词、接口计数器（CRC、drops 等）、IP/MAC 地址等常见内容。

## 性能说明

高亮渲染只覆盖终端可视区域（上下各保留少量缓冲行），每行最多渲染 32 处匹配，并按帧分批扫描；滚动和输出时增量更新，不对整个回退缓冲区做全量匹配。编写规则时仍建议：

- 优先使用文本匹配或带单词边界的正则，避免大范围回溯表达式。
- 用 `\|` 合并同颜色的关键字，减少规则条数。
- 颜色与终端主题底色保持足够对比度。
